# FRONTEND.md — NADAPROD frontend technical documentation

Everything under `web/`, served as plain static files by gin — **no bundler, no framework, no build step**. Pages are self-contained (inline `<script>`/`<style>`), with three exceptions on disk: the injected editor (`web/static/inject.js` + `inject.css`), the code workshop of the imported-sites editor (`web/static/sites-code.js`, §2.4) and the block studio, whose logic lives in native ES modules under `web/static/studio/` (§1). All product UI copy is in French — keep that convention.

Three application surfaces + a set of static marketing/legal pages:

| File | Route | Role |
|---|---|---|
| `web/home.html` | `/` | Public landing (marketing, FR/EN, light/dark) — « Le Signal » form posts to `/waiting-list` |
| `web/login.html` | `/login` | Login page (public) — `POST /api/login`, then redirect to `?next` (internal paths only) or `/sites` |
| `web/waiting-list.html` | `/waiting-list` | Public application form (name/email/project + honeypot) → `POST /waiting-list` |
| `web/studio.html` + `web/static/studio/*` | `/editor` · `/editor/<project>` | Block studio — the app *(requires session)* |
| `web/sites.html` | `/sites` | Imported-sites manager & visual/code editor host *(requires session)* |
| `web/drafts.html` | `/drafts` | Same manager, filtered to sites **without** a domain (drafts) *(requires session)* |
| `web/static/inject.js` `.css` | *(injected)* | In-page editor for imported sites |
| `web/static/sites-code.js` | `/static/*` | Code workshop (Monaco tabs + live preview) shared by `/sites` and `/drafts` (§2.4) |
| `web/static/i18n.js` + `i18n/{fr,en}.json` | `/static/*` | Shared i18n loader + translation files (see §0) |
| `web/about,legal,privacy,terms,solutions,opensource,404.html` | *(matching routes)* | Static brand/legal pages |
| `web/gfx/` | `/gfx/*` | Logo, favicon, images |

Auth: unauthenticated page loads are redirected server-side to `/login?next=…`; `sites.html` additionally boots on `GET /api/me` and self-redirects on 401.

External CDNs (the only network dependencies): Monaco from jsDelivr (`monaco-editor@0.52.2`, lazy-loaded) and the Tailwind Play CDN **only inside the studio's preview iframe / HTML export** (generated blocks use arbitrary classes). The app chrome itself is CDN-free: the app pages load `/static/tw.css`, a single purged build compiled by `bin/build.sh` from `tools/appcss/{tailwind.config.js,input.css}` — its `content` globs cover the app pages, **the studio's JS modules and `sites-code.js`**, which emit Tailwind-classed HTML (the shared `ink`/`vio` palette + the editor's `canvas-dots`/`scrollbar-thin` utilities — the old inline `tailwind.config` scripts are gone; **re-run the build after adding classes to app pages**). **Fonts are self-hosted**: every page loads `/static/fonts.css` (`@font-face` over the local mirror at `/webfonts/…` — Bebas Neue, Inter, JetBrains Mono, Space Mono, Space Grotesk); the app itself never calls `fonts.googleapis.com` — the one deliberate exception is `theme.js`'s `googleFontsHref()`, emitted into the client-built « Copier la page » output (a standalone file can't reach `/webfonts`; the server-side export localizes fonts instead). The mirror itself (`web/webfonts/`, ~1 400 TTF families, gitignored) ships its own « My Webfonts » browser page at `/webfonts/` (search, favorites, `@font-face` snippet generator; regenerated by `tools/mywebfont`).

Shared conventions in `/editor` and `/sites` (the studio's copies now live in `static/studio/core.js` and `panels.js` — `/sites` and `/drafts` still carry their own inline ones, see TODO §3): identical `toast(msg, ok)` snackbar, identical `loadMonaco()` loader, `$ = document.querySelector`, a single module-level state object `S`, event delegation through one `document` click listener with `data-*` attributes. (The `ink`/`vio` palette now lives solely in `tools/appcss/tailwind.config.js` — no page carries an inline `tailwind.config` anymore.)

## 0. i18n — `web/static/i18n.js` + `web/static/i18n/{fr,en}.json`

Every app page (home, login, waiting-list, editor, sites, drafts) loads `/static/i18n.js` in its `<head>`. Resolution: persisted choice (`localStorage['nadaprod-lang']`) else browser language (`navigator.languages[0]`, 2-letter), then **`en.json` for any key missing** from the loaded language (both files are fetched and shallow-merged, `en` under). The HTML ships French text as the static fallback — French visitors see zero flash, and the page stays readable even if the fetch fails. `document.documentElement.lang` is set to the resolved language.

- **Markup**: `data-i18n="key"` (innerHTML — values come from our own JSON, HTML allowed: links, `<span class="font-mono">`, `<br>`), and `data-i18n-placeholder|-title|-aria-label|-alt|-value|-content="key"` for attributes. Text next to an inline SVG icon is wrapped in a `<span data-i18n>` so applying doesn't wipe the icon.
- **JS**: global `t('key')` / `t('key', {name: value})` (`{name}` interpolation); an unknown key renders as the key itself (easy to spot). Page boots `await I18N.ready` before first render (`boot()` in sites, `init()` in editor; drafts wraps its `/api/me` fetch + `loadSites()` in `I18N.ready.then`).
- **Language switch**: `I18N.setLang('en')` (persisted, live re-apply) + `I18N.onChange(cb)` for JS-driven text — used by home's FR/EN toggle, animated hero and marquee (`applyDynamicTexts`).
- **Keys**: flat, page-prefixed (`studio.*` — the largest namespace, `sites.*` shared by drafts, `editor.*`, `code.*` for `sites-code.js`, `home.*`, `login.*`, `wl.*`, `gdpr.*`, `common.*`). `fr.json` is the exhaustive source of truth (452 keys); **`en.json` is fully translated** (the few identical values are proper nouns/symbols). Keep both files key-identical.
- **Out of scope (stays French)**: marketing/legal content pages (`about`, `legal`, …, documents rather than UI) and server-side strings (API error messages, block-catalog labels/presets from `prompts.go`). ⚠ `about.html` and `solutions.html` carry leftover unprefixed `data-i18n` attributes whose keys exist in neither JSON file — inert today (those pages don't load `i18n.js`), but they would blank content if it were ever added; strip them first.
- **GDPR banner on published sites**: i18n'd too, via the `gdpr.*` keys of the same JSON files — but the translations are **embedded at build time** into the injected script (published sites are standalone; see BACKEND.md §4.7 step 4). Visitor-side resolution: `?lang=xx` GET param (persisted) → stored choice → browser language → English.

## 1. Block studio — `web/studio.html` + `web/static/studio/*.js`

Served on `/editor` and `/editor/<projectId>`. The page is markup only; the logic is **native ES modules** (no bundler, no build step — `<script type="module" src="/static/studio/main.js">`). (The previous single-file studio, `web/index.html`, was deleted after the 2026-09-19 deployment.)

| Module | Role |
|---|---|
| `core.js` | State `S`, event bus (`on`/`emit`), `api()` + `ApiError{status, code, data}` (401 ⇒ back to `/login?next=`), toast (`aria-live`), modal helper (`openModal`, `confirmBox`, Esc/backdrop close, focus restore), block icons, `ago()` |
| `store.js` | Server persistence: boot/open/create, localStorage → server migration, serialized save queue with `rev`, conflict handling, `versions()` / `checkout()` |
| `preview.js` | The sandboxed preview iframe: shell document, postMessage bridge, incremental sync, stream updates, thumbnails (`thumb`/`fitThumbs`), CDN `pageHTML()` for "copy page" |
| `frame.js` + `frame.css` | Classic script running **inside** the iframe: block reconciliation, selection (block / element modes), in-place text editing, element replace/delete/parent, image swap, quality audit |
| `theme.js` | Design system: colour scales, Tailwind config object, `@font-face` from the local mirror, prompt payload |
| `generate.js` | Streaming generation, variants, page re-theme, targeted element retouch, actionable error panel, `commit()` |
| `structure.js` | Palette + structure list: click, drag-and-drop (reorder + insert from palette), keyboard |
| `panels.js` | Right panel: Générer / Code (Monaco) / Historique / Qualité / Marque (brand + design system + SEO), photo picker, frame message handlers |
| `exporter.js` | Projects dialog (open, new, import JSON, delete), export menu, publish dialog |
| `palette.js` | ⌘K command palette, ⌘Z / ⇧⌘Z |
| `main.js` | Entry point: wires the bus, loads `/api/blocks` + `/api/studio/config`, then `boot()` |

Import graph is acyclic: everything imports `core.js`; `main.js` is imported by nobody. **Tailwind classes used in these JS files are compiled into `web/static/tw.css`** (the modules are in the `content` globs of `tools/appcss/tailwind.config.js`) — after adding classes, re-run the CSS step of `bin/build.sh`.

### 1.1 Layout

Top bar: logo · **project switcher** (`#btnProjects`) · save state (`#saveState`, `aria-live`) · viewport toggle Bureau/Tablette/Mobile + **Retouche** mode toggle · model badge · **⌘K** · Sites link · **Exporter** menu (standalone HTML, ZIP site, React, Vue, copy page, project JSON, publish…). Left rail: palette (15 generators, « Section libre » last, scrollable, tiles are draggable) + structure list. Centre: the preview `<iframe id="preview" sandbox="allow-scripts">`. Right panel (24rem ⇄ 46rem): five tabs.

### 1.2 State & persistence

```js
S = { catalog, cfg,                       // /api/blocks, /api/studio/config
      project: {id, name, rev, publish, owner},  // the open project
      page: [{id, type, html, prompt, can_undo, can_redo}],
      brand, theme, seo,                  // project meta (theme normalized by theme.js)
      selectedId, viewport, mode: 'block'|'element', element, generating, tab }
```

- **The server is the source of truth** (`pkg/projects`, BACKEND §7). `boot()` first honours the site bridges (`?from`+`?path`, then `?site`), then runs the **localStorage migration** (`'nadaprod'`, or legacy `'windpage'` — which is deleted on the way; guarded by `'nadaprod:migrated'`), then opens, in order: the id in the URL, the last opened (`localStorage['nadaprod:lastProject']`), the most recent project, else a new empty project. `history.replaceState` keeps `/editor/<id>` in the address bar.
- **Writes**: `saveBlock(b, source)` and `saveMeta()` mark things dirty; `schedule()` turns them into jobs in **one sequential queue** — block PUTs first, then the meta PUT (the `order` can only place blocks the server already knows). Each job sends the known `rev` and stores the returned one. Typing (`source: 'edit'`) is debounced 500 ms and coalesced; every other source (generate, variant, code, retouch…) is scheduled immediately so it becomes its own history entry. `flush()` resolves when the queue is empty — called before undo, export, publish, project switch.
- **Failures**: network/5xx **and 429** ⇒ state "Hors ligne", exponential backoff, the job is retried; other 4xx ⇒ dropped with a toast; **409 `conflict` ⇒ everything stops** and a modal offers to reload (another tab/device changed the project — nothing is overwritten). `visibilitychange → hidden` flushes with `keepalive` (bodies < 60 KB); `beforeunload` warns while writes are pending.

### 1.3 Preview — an isolated iframe driven by postMessage

The iframe has `sandbox="allow-scripts"` **without** `allow-same-origin`: generated HTML/JS runs in an opaque origin (no cookies, no API, no parent DOM). The studio authenticates messages by `e.source === iframe.contentWindow` (the origin is `"null"`). `shell()` builds the host document: Play CDN (block classes are unpredictable), the theme's `tailwind.config`, `@font-face` rules pointing at `/webfonts` (CORS-enabled for that reason), `frame.css`, `#np-root`, `frame.js`. **The iframe is reloaded only when that shell changes** (theme, fonts, lang — `shellKey`); otherwise `np:sync` reconciles block wrappers (`<div data-np-block="id">`) by id: only changed blocks are re-rendered and the scroll position survives. `innerHTML` does not execute scripts, so `frame.js` re-creates `<script>` nodes of final blocks (header menu, banner close) — but not of partial streamed HTML; a `np:stream` frame clears the reconciliation cache, forcing a full re-render on the next `np:sync`. Inside the frame, every click is `preventDefault`ed and form submissions are blocked — the preview never navigates.

| Studio → frame | Frame → studio |
|---|---|
| `np:sync {blocks, selectedId, hint}` · `np:stream {id, html}` · `np:select {id, scroll}` · `np:mode {mode}` | `np:ready` · `np:block-click {id}` |
| `np:replace-el {html}` · `np:set-img {src, credit}` · `np:parent` · `np:delete-el` | `np:el-selected {id, tag, html, isRoot, isImg, photo, alt}` · `np:el-deselected` · `np:block-html {id, html, reason}` |
| `np:audit` | `np:audit-result {blocks:[{id, issues}], page}` |

Block HTML coming back from the frame (`np:block-html`) is serialized from a clone stripped of every editing artefact (`data-np-*`, `contenteditable`).

### 1.4 Generation — `generate.js`

- `generate()` → `POST /api/generate/stream`, SSE parsed from `fetch`'s `ReadableStream`. Each `delta` is accumulated; every ~120 ms `partial(raw)` (fence stripped, dangling tag cut, unfinished `<script>` dropped) is pushed with `np:stream`, so **the block builds up in the preview**. `done` carries the authoritative cleaned HTML → `commit(b, html, 'generate')`. "Arrêter" aborts the fetch. `⌘/Ctrl+Enter` in the brief.
- The request carries `brand`, `theme` (when enabled), `siblings` (the other generated blocks — server-side coherence summary), `images` (user toggle, shown only when a stock-photo provider is configured, persisted in `localStorage['nadaprod:images']`), and `current_html` (⇒ a second prompt iterates).
- **Errors are actionable, not toasts**: the server's `code` selects a title + explanation (`studio.err_<code>_title/_body`), the raw message is shown small, "Réessayer" is hidden for non-retryable codes (`auth`, `blocked`, `invalid`), `retry_after` is displayed when present.
- **Variants**: three parallel `POST /api/generate` with `variant: 1..3`, shown as scaled 1280-px thumbnails in a modal as they arrive; "Choisir" commits with source `variant` (undoable). Costs three rate-limit tokens.
- **Re-theme the page**: sequential `mode: 'retheme'` calls over every generated block with a progress modal; closing it stops; each block gets a `retheme` version. Needed once for blocks generated *before* the design system was enabled — afterwards, theme changes are instant (tokens).
- **Targeted retouch** (mode `element`): click an element in the preview → the Générer tab swaps to the retouch panel (tag, brief, parent ↑, delete, photo picker for `<img>`); `POST /api/generate` with `block: 'element'` and the element's `outerHTML`, then `np:replace-el`. Double-click edits text in place. Both come back as `np:block-html` → `commit(…, 'retouch' | 'edit' | 'image')`.

### 1.5 Structure — `structure.js`

Native HTML5 drag-and-drop: a structure row (reorder) or a palette tile (insert at the drop position); the indicator is a violet line above/below the hovered row. ↑ ↓ 🗑 buttons remain. Keyboard (the list is a `listbox`, the selected row is the tab stop): ↑/↓ select, **Alt+↑/↓ move**, Delete/Backspace removes, Enter focuses the brief. `addBlock()` refuses past the server's per-project cap (`S.cfg.max_block`, 60) with a toast. Clicking a block in the preview selects it (`np:block-click`).

### 1.6 Code tab — Monaco with textarea fallback

Unchanged in spirit: `loadMonaco()` lazy-loads from jsDelivr with the worker blob-proxy; the `<textarea>` stays if the CDN is unreachable; `⌘/Ctrl+S` = "Appliquer", which commits with source `code`. "Agrandir" widens the panel.

### 1.7 History — per-block versions

`Historique` lists the selected block's versions (source, relative time, prompt excerpt); **Comparer** opens a before/after modal (two thumbnails), **Restaurer** moves the pointer (`checkout {version_id}`). Undo/redo buttons and **⌘Z / ⇧⌘Z** (ignored while typing in a field or in Monaco) call `checkout {step: ∓1}`. `can_undo`/`can_redo` come back with every block write.

### 1.8 Quality score

The audit runs **in the frame** (it needs computed styles) and only reports what it can measure: WCAG AA contrast (effective background = alpha-composited ancestors; a gradient or background image ⇒ skipped, not guessed; 3:1 for large text), `<img>` without `alt`, links/buttons without an accessible name, form fields without a label, more than one / no `<h1>`, skipped heading levels. `panels.js` scores each block `100 − Σ(error 8, warning 4, info 1)`, averages, subtracts 4 more per page-level issue, and lists issues with a snippet; clicking a block jumps to it.

### 1.9 Design system, SEO — `theme.js`, Marque tab

`normalizeTheme` validates the stored theme and recomputes the two 11-stop scales (`scale(hex)`: same hue, **the picked colour is the 600 stop**, lighter stops move toward near-white, darker stops are fractions of its lightness). `tailwindConfig()` mirrors `export.TailwindConfig` (Go) — same structure, so preview and export agree. Fonts offered = the curated families actually present in the server's mirror. SEO fields are stored with the project and applied at export (empty ⇒ derived server-side).

### 1.10 Export, publish, projects, sites — `exporter.js`

`siteDialog()` (« Enregistrer dans un site… », first entry of the export menu) lists the account's sites (`GET /api/sites`, root also gets « — Nouveau site — » → `POST /api/sites/new`), pre-fills the last target (`project.publish.provider === 'site'`), warns and asks for an overwrite checkbox when the path already exists, then `POST /api/projects/:id/site`. `store.boot()` honours `?site=X&path=Y` (new project aimed at that page) and `?from=X&path=Y` (`POST /api/projects/from-page`, then the project opens) before the usual resolution.

#### Export, publish, projects

Exports are **server-side** (`POST /api/projects/:id/export`, after `flush()`): standalone HTML (compiled CSS), ZIP site, React or Vue components; warnings arrive in `X-Export-Warnings`, and `X-Export-Compiled` selects between the "compiled" and "CDN" success toasts. "Copier la page" is the only client-built output (CDN version, `pageHTML()`, Google Fonts link). The publish dialog pre-fills a remembered provider token; "remember in this browser" (pre-checked once one is stored) keeps it — and the Cloudflare account id, under a `<provider>:account` key — in `localStorage['nadaprod:publishTokens']`; it is never stored server-side. The projects dialog lists, opens, creates, imports a `*.nadaprod.json` backup and deletes (with confirmation).

### 1.11 Command palette — `palette.js`

`⌘K` / `Ctrl+K` (capture phase, so it wins over Monaco's chord prefix): add any block, generate, variants, undo/redo, retouch mode, quality, re-theme, tabs, viewports, exports, publish, projects. Accent-insensitive multi-word filter, ↑/↓/Enter.

## 2. Imported-sites manager — `web/sites.html`

### 2.0 Bridge to the studio

Header: a **Studio** link (`/editor`). List: **+ Nouveau site (studio)** (`#newSiteRow`, root — `prompt()` → `POST /api/sites/new` → `/editor?site=<id>&path=index.html`) and a **+ Page** button per site opening the native `<dialog id="newPageDlg">`: compose in the studio (`/editor?site=…&path=…`, the page is only created when the studio saves), copy an existing page or a blank page (`POST /api/sites/:id/pages`, then the editor opens on it). Edit mode: **+ Page** and **Studio** (`/editor?from=<site>&path=<page>`) next to the page selector. `drafts.html` got the same additions (and now loads `/api/me` like `sites.html`).

### 2.1 Two views, one page — role-aware

Boot (`boot()`): `GET /api/me` → module-level `ME = {email, root, sites}` (401 ⇒ redirect `/login?next=/sites`), header shows the email + a « Déconnexion » button (`POST /api/logout` → `/login`).

- **List view** (`#viewList`): dropzone (click or drag-drop → `upload(file)` → `POST /api/sites` multipart; **hidden for non-root**) + site cards from `GET /api/sites` — already filtered server-side to the account's sites (id, page count, domain badge, Consulter, Éditer; Supprimer with `confirm()` is root-only). Root also gets the **« Comptes » card** (§2.9). Only sites **with** a domain are listed here — domain-less sites live on `/drafts` (§2.8).
- **Edit view** (`#viewEdit`): page `<select>`, **Visuel · IA ⇄ Code** mode toggle, "Enregistrer la page", amber dirty dot, domain input + "Brancher le domaine" (**root-only** — users see the domain read-only in `#domainRO`), a **⚙ settings popover** (see §2.7, available to everyone), and a right aside (selected element info, Parent/Supprimer, AI retouch prompt, go-live info).

### 2.2 State

```js
ME = { email, root, sites }   // compte connecté, chargé au boot
S = { siteId, page, domain, dirty, hasSelection, aiBusy,
      saveResolve,        // pending resolver for the iframe HTML round-trip
      mode: 'visual'|'code',
      editor, settingValue,  // vestigial — declared but unused since CodeMode took over (§2.4)
      frameStale,         // file rewritten while in code mode → reload iframe
      settings }          // publication settings {compile, fonts, pwa, gdpr} (⚙ panel)
```

`openEditor(site)` takes the full site object from `sitesCache` (id, pages, domain, settings).

### 2.3 Visual mode — postMessage protocol with the injected editor

The iframe loads `/edit/<id>/<page>` (the real page + `inject.js`, see §3). All communication is `postMessage`, **origin-checked on both sides** (`location.origin`):

| Direction | Message | Meaning |
|---|---|---|
| iframe → parent | `wp:ready {title}` | injected editor booted — posted, but no parent handler consumes it today |
| iframe → parent | `wp:selected {tag, html}` | element selected (also re-sent after inline text edit); parent stores `lastSelectedHTML` |
| iframe → parent | `wp:deselected` | selection cleared |
| iframe → parent | `wp:dirty` | any input ⇒ `markDirty()` |
| iframe → parent | `wp:html {html}` | serialized page, resolves `getVisualHTML()` |
| parent → iframe | `wp:get-html` | request serialization (3 s timeout ⇒ resolves `null`) |
| parent → iframe | `wp:replace {html}` | swap the selected element with the AI result |
| parent → iframe | `wp:parent` / `wp:delete` | move selection up / remove element |

**AI retouch** (`aiEdit()`): `POST /api/generate` with `block:'element'`, the user brief, and `current_html = lastSelectedHTML`; the reply is pushed back with `wp:replace`. The element generator preserves the page's own stack (see BACKEND.md §3).

### 2.4 Code mode — the code workshop (`web/static/sites-code.js`, shared by `/sites` and `/drafts`)

`CodeMode.open(site, page, {html})` builds, inside `#codeWrap`, a tab bar + one Monaco editor (one *model* per file, view state saved/restored on tab switch) + a live preview pane (`/preview/<site>/<page>`, resizable, hideable). Tabs = the page (not closable) + every local CSS/JS it references (`GET /api/sites/:id/assets?page=`), and a « + » menu listing the site's other CSS/JS. **CSS is applied to the preview as you type** (250 ms debounce): the matching `<link>` gets a sibling `<style data-np-live>` holding the buffer and is disabled; back to the saved text ⇒ the link is re-enabled. HTML/JS changes turn the pane's dot amber; **saving (button or ⌘S) writes every dirty tab** (`PUT /api/sites/:id/file`, now accepting text assets — assets first, the page last so its republish sees them) and reloads the preview. Switching page in code mode opens a new workshop; `enterVisual` asks to save when anything is dirty. Public surface: `configure/open/saveAll/isDirty/close/pageHTML` plus `reload`, `layout` (called by both host pages on resize) and `dirtyFiles`. The old single-buffer implementation is gone from both pages (their `S.editor`/`S.settingValue` declarations remain but are unused).

State-safe toggle: `enterCode()` hands `CodeMode.open()` the serialized visual DOM when the visual page is dirty (**unsaved visual edits carry over** — the page tab then starts dirty against the file on disk), otherwise the workshop fetches the raw file (`/preview/…`, `cache:'no-store'`, no editor injection). `enterVisual()` asks to save (`confirm()` → `savePage()`) when any tab is dirty; `frameStale` (set when saving from code mode) forces the visual iframe to reload so it shows the saved files.

### 2.5 Saving — `savePage()`

Visual mode: the serialized iframe DOM → `PUT /api/sites/<id>/file {path, html}`. Code mode: `CodeMode.saveAll()` — one `PUT` per dirty tab (same endpoint, which now accepts text assets), assets first, the page last. Unsaved-changes guards: page switch, back button, and `beforeunload`. `⌘/Ctrl+S` works globally in the edit view.

### 2.6 Domain

"Brancher le domaine" → `PUT /api/sites/<id>/domain`; effective immediately (backend reloads its host map). `updateLiveInfo()` explains the DNS A-record step; after that, every "Enregistrer" is live instantly.

### 2.7 Publication settings — the ⚙ popover

The cog button next to "Brancher le domaine" opens `#settingsPanel`: four checkboxes (`data-setting="compile|fonts|pwa|gdpr"`) mapping 1:1 to the backend publish pipeline (local Tailwind compile, localized Google Fonts, generated PWA, GDPR notice — BACKEND.md §4.7). Each change immediately `PUT /api/sites/<id>/settings` with just that key; on failure the checkbox reverts (`saveSettings` keeps the previous value). The panel closes on any outside click. A footer note reminds that settings apply to the **published** version — the editor always works on the source, which is why toggles never change what the edit iframe shows.

### 2.8 Drafts — `web/drafts.html`

A near-copy of `sites.html` whose list view filters to sites **without** a domain (`!s.domain`; `sites.html` shows the inverse) and links « Aperçu » to `/preview/<id>/` instead of « Consulter ». The top-bar nav cross-links the two pages (« Sites en ligne » ⇄ « Brouillons »). It now boots on `/api/me` like `sites.html` (`ME` gates `#newSiteRow`), but the role-gating is still **partial**: no 401 self-redirect (a failed `/api/me` just yields `null`), the delete button and domain input render for everyone, and there is no `#domainRO`, accounts card or logout. Harmless (the server returns 403 and unauthenticated loads are redirected to `/login`), but the copy drift is tracked in TODO §3 alongside the shared-JS dedupe item.

### 2.9 « Comptes » card (root only) — `#accountsCard`

`loadAccounts()` fetches `/api/users` + `/api/waiting-list` in parallel. Per user: email, « Mot de passe… » (a `prompt()` → `PUT /api/users/:email {password}`), delete (`DELETE`, sites stay in place), and one checkbox per site from `sitesCache` — **each click saves immediately** (`saveAssignments` → `PUT {sites}` with the full checked list; on failure the panel re-renders from the server). Below: the add-account form (`POST /api/users`) and the waiting-list entries (newest first: date, email, name, message — all `esc()`-escaped). Delegated handlers: `data-upass` / `data-udel` on the document click listener, `data-assign` on a document `change` listener.

## 3. Injected editor — `web/static/inject.js` + `inject.css`

A single IIFE, idempotent (`window.__wp` guard), **zero state stored in the page**. Spliced before `</body>` by the backend (`injectTag`, ids `__wp_inject` / `__wp_style`) only on `/edit/` responses.

- **Hover**: mouseover/out toggle `data-wp-hover` (dashed violet outline via `inject.css`).
- **Select**: capture-phase click handler — `el(e)` filters out `<html>`, `<body>` and the injected nodes — `preventDefault`s the page's own links/buttons, sets `data-wp-selected` (solid outline), posts `wp:selected` with the element's `outerHTML`.
- **Inline text edit**: double-click sets `contenteditable`; `focusout` removes it and re-posts the updated `wp:selected`. Every `input` event posts `wp:dirty`. `Escape` deselects.
- **Serialization** (`serialize()`): clones `document.documentElement`, removes the two injected nodes and all `data-wp-hover`/`data-wp-selected`/`contenteditable` artifacts **from the clone**, returns `<!DOCTYPE html>` + `outerHTML`. What is saved is the page exactly as it will be served.
- **Commands from the parent**: `wp:get-html`, `wp:replace` (parses via an inert `<template>`, so any `<script>` in the AI reply does not execute; replaces and reselects), `wp:delete`, `wp:parent` (stops below `<body>`).

`inject.css` is 4 lines: outlines for `[data-wp-hover]`/`[data-wp-selected]` and their contenteditable focus style — all `!important`, so they win over the site's own CSS and are removed on save.

## 4. Public landing — `web/home.html`

Nearly self-contained (~740 lines: inline CSS + JS; loads `/static/fonts.css` and the shared i18n, and probes `GET /api/me` at boot to swap « Connexion » into « Mon compte » → `/sites`). Brutalist design with CSS custom properties.

- **Tab navigation**: `switchTab(id)` toggles `.active` on `<section id="tab-home|app|services|network">` and the fixed bottom nav — a single-page pseudo-router, no URL changes, inline `onclick` handlers.
- **i18n**: migrated to the shared system (§0) — the old inline `translations` dict now lives in `/static/i18n/*.json` under `home.*` keys. `toggleLanguage()` calls `I18N.setLang()` (**persisted now**); `applyDynamicTexts()` (registered via `I18N.onChange`) covers what `data-i18n` can't: the FR/EN button label, the animated hero (`home.hero{1..3}Top/Bot`) and the marquee.
- **Theme**: `data-theme="light|dark"` on `<html>`, CSS variables per theme, persisted in `localStorage['nadaprod-theme']`; `initTheme()` only applies a stored choice — without one, the system preference is honored purely by a CSS `prefers-color-scheme` media query, not JS.
- **Hero rotator**: `setInterval` (5 s) cycles three FR/EN message pairs with an opacity/translate transition on `#hero-title`.
- **« Le Signal » form** (Network tab): `joinWaitlist(event)` posts the email to `/waiting-list` (message tagged « inscription depuis la page d'accueil ») and swaps the form for a ✓; a discreet link below it leads to the full `/waiting-list` page.

The other static pages (`about`, `legal`, `privacy`, `terms`, `solutions`, `opensource`, `404`) follow the same visual language, each self-contained; they contain no API calls. `404.html` is also gin's `NoRoute` fallback.

## 5. Cross-cutting notes

- **Security posture**: the app pages sit behind session auth (BACKEND.md §0/§5); role gating in the UI (`ME.root`) is cosmetic — every rule is enforced server-side. Generated block HTML is **not** trusted: the studio preview is a `sandbox="allow-scripts"` iframe without `allow-same-origin` (opaque origin — no cookies, no API, no parent DOM), driven by postMessage and authenticated by `event.source` (§1.3); server-side, `cleanHTML` + `Sanitize` strip chatter and the scripts a block type is not allowed to carry. Thumbnails (variants, compare) use the same sandbox.
- **Failure modes handled**: backend unreachable at studio boot (toast), Monaco CDN down (textarea fallback in the studio; explicit refusal to enter code mode in /sites), generation errors (an actionable panel keyed on the server's error `code`, §1.4), save failures (offline state + backoff; 409 ⇒ reload prompt, §1.2), iframe not answering `wp:get-html` (3 s timeout, save aborted with a toast).
- **Known quirks and planned improvements are tracked in TODO.md** — notably the duplicated Monaco/toast/config code between the two editors and the Tailwind-CDN-in-production issue.
